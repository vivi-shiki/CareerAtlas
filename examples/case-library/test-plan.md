# Case Library Acceptance

## Content and import

- Each case has an explicit historical or fictional notice, a stable key and a dataset version.
- Historical claims link to an identified source; skill classifications are not certifications.
- Fictional metrics are visibly labeled and never represented as actual execution evidence.
- Initial import creates only the two dedicated identities and their records.
- Repeat import preserves identity, record and publication counts and does not erase owner edits.
- Alex's priority-scheduling proposal stays unconfirmed and unpublished.
- The private marker `ALEX-NOT-PUBLIC-482` is absent from public projections, sources and browser content.
- Runtime credentials appear only in the ignored manifest, never in the HTML index or tracked files.

## Visitor interactions

1. Open each published portfolio in a fresh unauthenticated session.
2. Verify the historical/fictional notice, three projects and expected selected records (Grace: three; Alex: five).
3. Open a project, a skill and a source. Check that the detail view is confined to this publication.
4. Check readable layout at desktop and mobile widths; switch among the three interface languages.
5. Confirm that linked historical evidence points to Yale or CHM; fictional statements are labeled as such.
6. Verify Agent availability separately from content rendering. Availability does not prove provider success.
