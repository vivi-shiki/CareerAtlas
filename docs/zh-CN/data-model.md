# 数据模型与发布生命周期

可编辑职业记录和已发布版本均存放在 PostgreSQL 中。通用的 `/p/{slug}` 页面请求 `GET /api/public/{slug}`，后端查找该发布记录并返回当前允许访问的快照。增加人物不需要新增页面组件。

## 主要数据表

| 数据表 | 关系与用途 |
| --- | --- |
| `users`、`profiles` | 登录身份，每个用户一份个人档案 |
| `projects`、`experiences` | 所有者拥有项目；经历属于同一所有者的项目 |
| `skills`、`skill_aliases`、`experience_skill` | 按所有者隔离的技能及别名，以及经历和技能的多对多关联 |
| `evidence` | 经历附带的链接或陈述；提供链接不等于独立验证 |
| `record_versions`、`experience_revisions` | 已确认来源版本及后续修订历史 |
| `publications`、`publication_snapshots`、`publication_items` | 公开标识与状态、当前快照、选定字段和来源版本引用 |
| `idempotency_keys`、`audit_events` | 重复请求处理与业务操作审计 |
| `capture_drafts`、`preparations`、`prepared_answers`、`answer_versions`、`practice_sessions`、`opportunities` | P1 私有素材、准备、练习及独立发布的机会页面 |
| `agent_conversations`、`agent_runs`、`owner_ai_runs` | 有范围限制的会话、排队任务和本人辅助建议 |

实际表结构以[数据库迁移](https://github.com/vivi-shiki/CareerAtlas/tree/main/database/migrations)为准。核心迁移定义外键和唯一性约束，后续迁移增加修订保护、Agent 存储及 P1 表。核心编辑数据使用关系字段与关联表，日期精度、快照和建议载荷也使用 PostgreSQL JSONB。这是数据库中的存储形式，与写死在前端的 JSON 示例不同；案例 JSON 文件只是可选的导入素材。

```text
用户 -> 档案
     -> 项目 -> 经历 -> 证据
                    <-> 技能（experience_skill）
                    -> 已确认记录版本
发布记录 -> 当前快照 -> 选定的版本化条目
公开页面 / 问答 -> 该发布记录允许访问的内容投影
```

## 确认与发布流程

1. **草稿**：私下保存未完成内容，不要求编造未知成果。
2. **确认**：核对标题、项目、记录类型、发生时间及精度、个人行动，保留确认版本。
3. **预览**：选择已确认记录，并明确选择档案、经历与项目字段。
4. **发布**：校验预览摘要，在事务中创建快照及条目。
5. **修改**：后续编辑使当前经历变为草稿，但不会替换已经发布的版本。
6. **重新发布**：审核新的选择后，显式更新公开内容。
7. **撤销**：停用发布记录；删除来源或撤销其对外访问，也会移除相关在线引用。

归档是独立的时间戳状态操作，不等同于撤销公开访问。撤销不能消除访客已经下载或看到的副本。详见[发布流程](./publishing.md)。

## 一致性与公开规则

- 复合所有权引用防止跨用户关联项目、经历和技能。
- `expected_version` 检测过期更新；同一所有者的操作在事务中串行处理。
- 确认版本与发布版本分开；预览摘要可发现正式发布前的来源变化。
- 幂等键允许重放相同发布请求，内容冲突的键重用会被拒绝。
- 公开项目、技能数量与引用从选定条目生成，不查询所有者的全部草稿。
- 私人备注不能被选为公开字段，私人准备要求和未选择的机会内容不进入公开问答。
- 时间保留年、月、日精度，证据链接与本人陈述保留不同来源类型。

## 可检查的示例

录入一条虚构贡献，确认后只发布个人行动、技能与证据。私下修改成果时，公开页面仍应显示选定的已发布版本；审核后重新发布才更新，撤销访问后应不可用。请在独立的本地测试数据上操作，不修改他人的记录。

组织成员、指定接收人授权和第三方确认属于规划中的 P2，不代表本章已实现对应数据表。参见[功能全览](./roadmap.md)、[后端代码说明](./backend.md)及[验证用例](./testing.md)。
