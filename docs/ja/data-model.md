# データモデルと公開ライフサイクル

編集可能な職務記録と公開済みバージョンをPostgreSQLに保存します。共通の `/p/{slug}` ページが `GET /api/public/{slug}` を呼び、サーバーは該当する公開記録から現在許可されたスナップショットを返します。人物の追加に個別の画面コンポーネントは不要です。

## 主なテーブル

| テーブル | 関係と用途 |
| --- | --- |
| `users`、`profiles` | ログイン情報とユーザーごとの一つのプロフィール |
| `projects`、`experiences` | 所有者のプロジェクトと、同じ所有者のプロジェクトに属する経験 |
| `skills`、`skill_aliases`、`experience_skill` | 所有者別のスキル・別名、経験との多対多の関連 |
| `evidence` | 経験に添付したリンクや本人の記述。リンクの登録は独立した検証ではありません |
| `record_versions`、`experience_revisions` | 確定した情報源のバージョンと変更履歴 |
| `publications`、`publication_snapshots`、`publication_items` | 公開用識別子と状態、有効なスナップショット、選択項目と情報源バージョン |
| `idempotency_keys`、`audit_events` | 重複リクエストの処理と業務操作の監査記録 |
| `capture_drafts`、`preparations`、`prepared_answers`、`answer_versions`、`practice_sessions`、`opportunities` | P1の私的なメモ、準備、練習、個別公開する応募機会 |
| `agent_conversations`、`agent_runs`、`owner_ai_runs` | スコープ付き会話、キュー処理、本人向け提案 |

実際の定義は[マイグレーション](https://github.com/vivi-shiki/CareerAtlas/tree/main/database/migrations)を参照してください。基本の外部キー・一意制約に加え、後続のマイグレーションで変更保護、Agent、P1のテーブルを追加します。編集データはリレーショナルな列と関連で管理し、日付精度、スナップショット、提案の内容にはPostgreSQL JSONBも使用します。これはDB内の保存形式であり、フロントエンドに固定したJSONデータではありません。ケースのJSONファイルは任意のインポート素材です。

```text
ユーザー -> プロフィール
         -> プロジェクト -> 経験 -> 根拠
                                <-> スキル（experience_skill）
                                -> 確定バージョン
公開記録 -> 有効なスナップショット -> 選択したバージョン付き項目
公開ページ / Q&A -> その公開記録で許可された投影
```

## 確定と公開の流れ

1. **下書き**：未完成でも私的に保存でき、不明な成果を補う必要はありません。
2. **確定**：タイトル、プロジェクト、記録種別、精度付きの発生時期、個人の行動を確認し、確定バージョンを残します。
3. **プレビュー**：確定した記録と、プロフィール・経験・プロジェクトの公開項目を選択します。
4. **公開**：プレビューのダイジェストを検証し、トランザクション内でスナップショットと項目を保存します。
5. **編集**：後の編集は現在の経験を下書きに戻しますが、公開済みバージョンを置き換えません。
6. **再公開**：新しい選択内容を確認して、明示的に更新します。
7. **取り消し**：公開を無効にします。情報源の削除や対外アクセスの取り消しも、依存するオンライン参照を除外します。

アーカイブは別のタイムスタンプによる状態管理で、公開取り消しとは異なります。取り消しても、訪問者が保存・閲覧済みのコピーは回収できません。[公開のガイド](./publishing.md)も参照してください。

## 整合性と公開範囲

- 所有者を含む複合参照により、他人のプロジェクト・経験・スキルとの関連付けを防ぎます。
- `expected_version` で古い更新を検出し、同じ所有者の操作をトランザクション内で直列化します。
- 確定と公開のバージョンは別です。公開前の変更はプレビューのダイジェストで検出します。
- 同じ公開リクエストは冪等キーで再送でき、異なる内容でのキー再利用は拒否します。
- 公開プロジェクト、スキル件数、引用は選択項目から導出し、所有者の全下書きを検索しません。
- 私的メモは公開項目に選択できません。準備用の非公開要件や未選択の応募機会の内容は公開Q&Aに入りません。
- 年・月・日の精度を維持し、根拠リンクと本人の記述の由来を区別します。

## 確認例

架空の貢献を登録・確定し、個人の行動・スキル・根拠だけ公開します。成果を私的に編集しても公開内容は変わらず、確認して再公開すると更新され、取り消すと利用できなくなります。別のローカルテストデータで試し、他人の記録は変更しないでください。

組織メンバー、指定相手へのアクセス許可、第三者確認はP2の計画で、本章はそれらのテーブルの実装を主張しません。[機能一覧](./roadmap.md)、[バックエンド](./backend.md)、[検証ケース](./testing.md)へ進めます。
